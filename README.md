# 电影院排片与售票管理系统

数据库原理课程设计，采用 Java Swing、JDBC 和 SQL Server。系统支持普通用户注册、自主购票与个人订单，以及管理员、售票员使用的基础资料维护、排片、售退票、经营统计和状态日志。付款为模拟确认。本次扩展只修改系统与开发说明，课程设计任务书保持原样。

## 项目范围

采用 Java 前台与 SQL Server 数据库，面向单影院业务，付款采用模拟方式。

- 影片、影厅、座位和场次管理，排片冲突检查。
- 座位图展示、选座售票，防止同一场次座位重复售出。
- 开场前退票、座位释放及订单查询，保证事务一致性。
- 售票量、净票房、上座率统计和影片票房排行。
- 普通用户注册登录、自主选座购票、查看自己的订单和开场前退票。
- 普通用户、售票员、管理员三种角色，以及数据完整性约束、存储过程和触发器。

## 在当前电脑运行

双击 **启动系统.cmd**。数据库为 `CinemaCourseDB`，连接配置保存在已被 Git 忽略的 `config/application.properties`。

| 应用账号 | 初始密码 | 权限 |
| --- | --- | --- |
| admin | Cinema@2026 | 管理员：全部业务及基础资料、排片和日志 |
| cashier | Cinema@2026 | 售票员：售退票、订单和统计 |

以上是演示应用账号，不是 SQL Server 登录账号。侧栏可修改密码；修改后需相应调整自动测试的登录数据。演示数据含 3 部虚构影片、2 个影厅、128 个座位及初始化次日的 6 个场次。场次过期后管理员可新增未来场次，不应重新初始化数据库。

普通用户在登录页选择注册入口，自行填写账号、显示名称、密码及确认密码。账号为 3–30 位英文字母、数字或下划线，显示名称 1–50 字，密码 10–128 位。注册只能创建 `CUSTOMER` 角色，不能自行选择管理员或售票员身份。注册成功后进入购票界面；同一个程序会根据登录角色显示相应功能。

普通用户可以浏览影片和未来场次、选座模拟付款、查看“我的订单”、整单退还自己的未开场订单和修改密码。普通用户不提供影院经营统计、基础资料维护和日志入口，也不能通过业务服务读取这些受限内容。

## 构建与部署

需要 JDK 17+、SQL Server 2017+、Windows PowerShell 和 sqlcmd。本机使用 JDK 25 与 SQL Server 2025。

```powershell
# 第一次下载微软 JDBC 依赖、复制本地配置模板、编译
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Setup.ps1
# 有创建数据库权限的 Windows 账号执行，已有数据库时拒绝覆盖
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Init-Database.ps1
# 根据本机环境编辑 config/application.properties 后运行
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Run.ps1
# 修改源码后重新编译
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1
```

已有首版数据库升级普通用户功能时，运行 `scripts/Upgrade-Customer.ps1`。该脚本先执行 `database/004_customer_role.sql` 扩展角色约束，再更新 `002_procedures.sql` 中的注册和退票过程，保留现有账号、影片、场次和订单，不重新初始化数据库。新部署使用更新后的初始化脚本。

脚本优先使用 `JAVA_HOME`，本机也识别 `D:\java_develop\jdk`。提供 `pom.xml` 便于 IDE 导入，PowerShell 构建不依赖 Maven 安装。微软驱动来自 Maven Central；其他电脑的连接配置可参考[微软 JDBC 文档](https://learn.microsoft.com/en-us/sql/connect/jdbc/setting-the-connection-properties)。

当前电脑 SQL Server 仅监听 `127.0.0.1:1433`，已按用户授权启用 Windows＋SQL 混合登录；未启用 sa 或外部监听。应用数据库账号 `cinema_app_local` 仅映射课设数据库，具有读取、存储过程执行和密码列更新权限，没有服务器角色。测试账号 `cinema_test_local` 仅在该库具有所有者权限，用于建立、验证及清理测试数据。随机 SQL 密码只保存在本地忽略文件中，不应提交到 GitHub。

`Enable-LocalSql.ps1` 与 `Configure-LocalSqlLogin.ps1` 是本机环境配置脚本，绑定默认实例 `MSSQL17.MSSQLSERVER`，涉及服务重启，其他电脑不要直接运行。日常构建与启动不修改这些系统设置。

## 关键规则

- 影厅布局为 1–20 排、每排 1–30 座；首次排片前可以停用座位，已有场次后冻结容量，保证历史统计一致。
- 排片包含影片时长和散场间隔，时间占用不能重叠，区间恰好相接允许排片。
- 每笔订单 1–50 个不同座位，场次锁、事务及有效票唯一索引共同防止重复售座。界面选座尚不占座，提交时以数据库结果为准。
- 开场前允许整单退票并释放全部座位；禁止重复退票及开场后售退票。普通用户只能查询和退还自己创建的订单；管理员与售票员保留全影院订单处理权限。
- 自主购票时，`Orders.UserId` 由已登录身份确定，不能由页面指定其他购票人。个人订单查询按该编号筛选，退票存储过程再次检查普通用户的订单归属。
- 已有任何历史订单的场次不能修改或删除；更改影片片长不会追溯改变已排片场次的结束时间。
- 订单按创建日期查询，统计按开场日期查询，起止日期均含当天。累计售票含已退票；净票房仅计有效票；上座率按有效票数除以所选场次可售座位总数计算。

GitHub 仓库保存源码、数据库脚本和开发说明。`lib/`、`build/`、`.tools/`、本地数据库配置、数据库备份及 `.taskbook/` 排版文件均已忽略；老师材料、填报资料、聊天截图与压缩包仅保存在本地。
