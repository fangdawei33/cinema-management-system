# 普通用户功能验证记录

验证日期：2026 年 11 月 9 日。普通用户功能已在原 Java Swing 系统中完成，原课程设计任务书没有修改。

## 已实现

- 登录页提供普通用户注册。填写账号、显示名称、密码和确认密码后，自动进入购票页面；注册固定创建 CUSTOMER 角色，不提供工作人员角色选择。
- 普通用户按影片名称筛选未开场场次、查看座位、选座并模拟付款。订单归属由当前登录身份确定。
- “我的订单”在查询时强制筛选当前用户；开场前整单退票时，存储过程再次核验订单归属。
- 普通用户可以修改密码，没有影院经营统计、基础资料管理、排片和日志入口。
- 管理员及售票员仍可处理影院订单，包括协助普通用户退票；日志记录实际操作者。

## 实际验证结果

执行 `scripts/Test.ps1`，原有 **47 项**检查与新增 **39 项**普通用户检查均通过，共 **86 项**。记录保存在 `.tools/customer-regression-result.txt`。

新增检查覆盖注册输入校验、重复及并发注册、密码哈希与随机盐、登录与修改密码、可售影片/场次浏览、内部数据访问限制、订单创建人、两个用户之间的订单隔离、用户无法退还他人或柜台订单、退票释放座位及重新售出、工作人员协助退票和日志操作人。失败权限检查未改变订单及日志。测试使用真实 SQL Server，并清理自己创建的临时用户和业务记录。

执行 `scripts/Preview.ps1`，工作人员页面复查通过，并自动走通登录页注册按钮、注册弹窗提交、等待期间禁用重复提交、注册后自动登录、仅两个普通用户业务页面，以及新用户“我的订单”为空。注册、购票及个人订单截图位于 `build/screenshots/customer-*.png`，已检查显示效果。

这些自动检查不代替全量人工验收。密码确认不一致等弹窗分支仍可按 `docs/验收清单.md` 手工复核。系统仍为可信本机环境下的课设应用，支付模拟；应用账号权限不等于独立 SQL Server 登录隔离，不能直接作为公网系统部署。
