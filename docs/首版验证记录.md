# 首版验证记录

验证日期：2026 年 11 月 8 日。此文记录开发过程中实际执行的验证，不代替三位同学个人操作、报告或答辩记录。

## 环境与启动

- Java 25.0.1 编译，目标字节码 Java 17；Microsoft JDBC Driver 13.4.0.jre11。
- 本机 SQL Server 2025 默认实例，独立数据库 `CinemaCourseDB`。
- TCP 限定为 `127.0.0.1:1433`，采用 Windows＋SQL 混合认证。未增加外部监听、未启用 sa。
- 本机 Windows 集成认证在 sqlcmd 下可用，但 Java 原生认证出现 SEC_E_NO_CREDENTIALS，因此在用户许可后配置了独立 SQL 账号。日常桌面应用不需要管理员权限。
- 应用账号具有该库读取、存储过程执行和应用密码列更新权限；测试账号单独拥有该库权限，方便清理测试夹具。两者均没有服务器角色。

截图位于 `build/screenshots/`。已人工查看页面截图，调整可售场次的开场时间列宽及座位按钮间距。页面加载检查不等同于全量鼠标操作验收，新增、修改、删除弹窗和真实演示流程仍应由三位同学按验收清单逐项操作。

## 当前边界

- 本机演示版，付款模拟，退票为整单退票，不提供会员、优惠、真实支付或公网自助购票。
- 登录账号的角色检查不等于独立数据库身份；不要把本地数据库凭据交给不受信任的客户端。
- 应用修改密码功能已实现；本轮自动测试验证了 PBKDF2 算法，尚未覆盖修改密码弹窗的完整手工操作。
- 新增场次必须在未来，演示场次过期后由管理员重新排片。
- 本轮未执行 GitHub 提交或推送，也未生成三人的个人结课报告。
